# Лабораторная работа 5 Форматы данных

В проекте «Учёт прихода и расхода материалов» реализован экспорт операций из SQLite в JSON, CSV, XML и YAML. Цель работы — получить одни и те же связанные данные в табличном и вложенном представлениях и проверить корректность сериализации.

## Выбранные данные

Основная таблица — `operations`. Каждая операция содержит дату, тип `IN` или `OUT`, комментарий и ссылки на ответственного пользователя и контрагента. Для прихода контрагентом является поставщик, для расхода — подразделение.

Таблица `operation_items` связывает операцию с материалами и хранит количество каждого материала. Поэтому результат экспорта представляет одну операцию как объект со списком позиций.

В поставляемых тестовых данных находятся четыре операции и одиннадцать позиций. Материалы — цемент, кабель и перчатки. Две операции фиксируют приход, две — расход. Если пользователь добавил новые записи в приложении, экспорт включает их автоматически.

## Получение данных

Запрос в `database/export_query.sql` использует `LEFT JOIN` для соединения `operations`, `suppliers`, `departments`, `users`, `operation_items` и `materials`. Он извлекает все операции, в том числе без позиций. Ненайденная необязательная связь даёт `NULL`.

Запрос выполняется в `OperationRepository.get_export_rows()`. Репозиторий возвращает данные и имена колонок; благодаря этому CSV содержит заголовки даже при отсутствии операций. Для ответственного пользователя извлекаются идентификатор, ФИО и роль.

## Преобразование структуры

Функция `build_nested_data()` группирует строки JOIN по `operation_id`. Поля позиции помещаются в список `items`. Псевдонимы SQL определяют вложенность:

| Псевдоним SQL | Поле в объекте | Колонка CSV |
| --- | --- | --- |
| `operation_date` | `operation_date` | `operation_date` |
| `supplier__name` | `supplier.name` | `supplier.name` |
| `user__full_name` | `user.full_name` | `user.full_name` |
| `items__quantity` | `items[].quantity` | `items.quantity` |
| `items__material__name` | `items[].material.name` | `items.material.name` |

В JSON, XML и YAML отсутствующий поставщик или подразделение записывается как `null`. У операции без позиций остаётся пустой список `items`. При группировке повторная позиция с тем же идентификатором не добавляется дважды.

## Форматы результата

| Формат | Представление | Средство Python |
| --- | --- | --- |
| JSON | Массив операций с вложенными объектами и списком позиций | `json.dump` |
| CSV | Одна строка на позицию, связанные поля в отдельных колонках | `csv.DictWriter` |
| XML | Корень `data`, элементы `item`, вложенные теги и атрибуты типов | `xml.etree.ElementTree` |
| YAML | Список операций с вложенными словарями и списками | `yaml.safe_dump` из PyYAML |

Сериализация преобразует Python-словари и списки в текстовые файлы. Обратное чтение файлов парсерами проверяет десериализацию.

JSON, XML и YAML сохраняют структуру. В CSV реквизиты операции повторяются для каждой позиции; числа читаются из CSV как строки и при необходимости преобразуются обратно. Необязательные значения `NULL` представлены в CSV пустыми ячейками. CSV не различает `NULL` и пустую строку, поэтому он предназначен для просмотра и табличной обработки.

В XML атрибут `type` различает объекты, массивы, строки, числа, логические значения и `null`. Например, пустая строка записывается как элемент с `type="string"`, а отсутствие значения — с `type="null"`. Так можно восстановить данные без смешения этих значений.

Кириллица сохраняется в UTF-8. JSON использует `ensure_ascii=False`, YAML — `allow_unicode=True`. В CSV добавлен BOM для распознавания кодировки табличными редакторами. Кавычки, запятые, переносы строк и символы XML экранируют стандартные средства сериализации.

## Запуск

В терминале PyCharm из корня проекта:

```bash
python -m pip install PyYAML
python src/export_data.py
```

Либо запустить файл `src/export_data.py` кнопкой Run. Папка `out` создаётся в корне проекта независимо от рабочего каталога PyCharm. Файлы результата:

```text
out/data.json
out/data.csv
out/data.xml
out/data.yaml
```

Дополнительные параметры:

```bash
python src/export_data.py --db data/materials.db --out out
```

Относительные пути, явно переданные в параметрах, отсчитываются от текущего рабочего каталога. Без параметров используются пути относительно корня проекта.

Повторный запуск обновляет четыре файла. Существующая база только читается. Если стандартной базы ещё нет, точка входа создаёт её из `schema.sql` и `seed.sql`. Если явно указать неправильный путь к базе, программа завершится с сообщением об ошибке.

## Универсальность кода

Функции `export_json()`, `export_xml()` и `export_yaml()` принимают готовые словари и списки и не содержат перечня полей операций. `export_csv()` принимает плоские строки и названия колонок из результата SQL.

Чтобы экспортировать другую основную таблицу со связанным списком, требуется заменить запрос и передать в `build_nested_data()` имена основного ключа, списка и ключа позиции. Например: `id_field="order_id"`, `collection_field="lines"`, `collection_id="line_id"`. Добавление обычных или вложенных полей через псевдонимы SQL не требует переписывания функций сериализации.

Текущая группировка поддерживает один связанный список на основной объект и вложенные объекты внутри него. Для нескольких независимых списков следует отдельно собирать каждую связь, чтобы JOIN не перемножал позиции.

## Проверка

```bash
python -m unittest discover -s tests -v
```

Тесты ЛР5 проверяют создание четырёх файлов и папки, все четыре операции и одиннадцать позиций, связанные сведения о материалах и контрагентах, совпадение JSON с XML и YAML после обратного чтения, содержание CSV и русские символы. Дополнительно проверяются специальные символы, пустая база, операция без позиций, повторный экспорт изменённых данных, другая структура группировки и запуск из другого каталога.

Отдельная проверка сравнивает хэш файла БД до и после экспорта. Это подтверждает, что экспорт не изменяет исходную базу.

Проверка выполнена 10 ноября 2026 года. В итоговой папке `out` сформированы четыре файла: JSON, XML и YAML содержат по четыре операции с одиннадцатью позициями, CSV — одиннадцать строк данных и заголовок. После обратного чтения содержимое JSON, XML и YAML совпало. Все восемь тестов экспорта завершились с результатом `OK`; ранее существовавшие тринадцать тестов приложения также прошли.

## Демонстрация на сдаче

1. Показать таблицы `operations`, `operation_items` и `materials`, объяснить их связи.
2. Открыть `database/export_query.sql`, показать JOIN и псевдонимы вложенных полей.
3. Запустить `src/export_data.py` и показать четыре файла в `out`.
4. В JSON показать операцию, поставщика или подразделение и список `items`.
5. В CSV показать повторение реквизитов операции для разных материалов.
6. Сравнить ту же операцию в XML и YAML.
7. Запустить тесты и показать результат `OK`.
